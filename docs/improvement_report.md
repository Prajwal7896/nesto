# Nesto AI Smart House Planning System: Architectural & System Improvement Report

This report outlines the current system limitations identified in Nesto's spatial design, CAD rendering, and user experience layers, and describes the concrete engineering changes proposed to convert the platform into a production-grade generative architectural utility.

---

## 1. Analysis of Current Limitations

### 1.1 Why Plans Look Like Simple Rectangles
- **Predefined/Static Room List**: `LayoutPlanner` (`backend/api/rag/planner.py`) currently uses a hardcoded, static list of rooms (`create_rooms`) with fixed coordinates (e.g., `living_room` always at `500, 500` with dimensions `5000, 4500`). It ignores the dynamically extracted room counts and plot dimensions from user requirements.
- **Greedy Row-by-Row Packing**: `LayoutOptimizer` (`backend/api/rag/optimizer.py`) relies on a linear 2D row-based box packer. It places rooms sequentially (`Room A` -> `Room B` -> `Room C`) until it hits the plot width boundary, then starts a new row.
- **Lack of Zoning**: There is no concept of architectural zoning. Public spaces (living rooms), private spaces (bedrooms), and service areas (bathrooms/kitchens) are scattered based on packing order rather than logical adjacency.
- **No Circulation Routing**: The system lacks an algorithm for corridors, entrance lobbies, or staircases, resulting in rooms packed directly against each other with no functional access.

### 1.2 Why CAD Outputs Look Like Simple Blocks
- **No Wall Thickness**: `WallGenerator` (`backend/api/rag/renderer/wall_generator.py`) draws room borders as single lines on a generic layer. It does not generate double-line walls or distinguish between outer perimeter walls (typically 230mm) and internal partitions (typically 115mm).
- **Missing Openings**: Doors and windows are never dynamically generated by the planner or placed in the CAD model. Hinge points, swing arcs, and frame cutouts are completely absent.
- **Crude Furniture Primitives**: `FurnitureGenerator` draws generic rectangles in the exact center of rooms (often overlapping labels) instead of snapping furniture to walls (e.g., bed against a wall, wardrobe along a boundary).
- **Text Overlap**: Room names and area labels are written on top of each other at the exact centroid of each room polygon, rendering them unreadable.
- **Lack of Annotations**: Drawings lack a north compass indicator, drawing border margins, dimension annotations, or a sheet title block.

### 1.3 Frontend Visualization Limits
- **Static Display**: The frontend displays a single PNG image without user-friendly interactions like zooming, panning, or viewing multi-format source links (SVG/DXF/JSON metadata).
- **No Project Metrics**: The UI does not display key project statistics, room area breakdowns, Vastu compliance scores, or material cost estimations.

## 2. Proposed Improvements & System Architecture

### Before vs. After System Flow

#### Before Architecture:
```
User Prompt ──► LLM Requirements ──► Static Room Coordinates ──► Row Packing ──► Single-line Render ──► Static PNG
```

#### After Architecture (Production-Grade):
```
User Prompt 
    │
    ▼
LLM Requirements & RAG Grounding
    │
    ▼
Parametric Zoning Grid Planner (Buildable Area, Setbacks, Floors)
    │
    ▼
Adjacency & Orientation Optimizer (Vastu directions, Corridor routing)
    │
    ▼
Validation Engine (Tri-Score evaluation: Architecture, Vastu, Efficiency)
    │
    ▼
Universal Wall/Opening Compiler (Outer/Inner Wall solver, Door corner placements, Window centrings)
    │
    ▼
Detailed CAD Renderer (ezdxf A-WALL, A-DOOR, A-WINDOW, A-FURN, A-DIM layers; double-lines)
    │
    ▼
Architectural Sheet Decorator (Sheet borders, North arrow, Scale bar, Title block)
    │
    ▼
Multi-Format Exporter (DXF, clean white-bg SVG, and high-DPI rasterized PNG)
    │
    ▼
Interactive Frontend Dashboard (Zoom/Pan canvas, CAD file downloads, statistics, Vastu score breakdown)
```
